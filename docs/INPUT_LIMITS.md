# 入力制限と復旧の受け入れ確認

2026-10-10（日本時間）。日常利用の MVP に対する、読み込み前・展開前の上限と
失敗時のデータ保持を記録する。制限を超える文書は明示的なエラーで拒否する。
上限には保守的な見積もりを含むため、実際の表示量が小さいファイルも拒否することがある。

## Writer

| 対象 | 上限 |
| --- | --- |
| JSON / DOCX / ODT 入力 | 64 MiB。ストリームも上限+1バイトで停止 |
| DOCX / ODT ZIP | 4096部品、宣言された展開容量128 MiB。ZIP64は非対応 |
| XML部品 | 各8 MiB、深さ128、全体で50000要素・4 MiBの文字列予算 |
| 文書モデル | 1000セクション、50000項目、本文・書式文字列など合計4 MiB |
| 1段落 | 64 KiBの本文。ヘッダー／フッターと表のセルも含む |
| 表 | 1行256セル。行・セル・段落・runを項目数に含める |
| フロー配置 | 最大フォント、改行、余白、表幅から保守的に見積もって2000ページ以下 |
| 繰り返しマージン文字列 | ページ見積もり×ヘッダー／フッター文字数で4 Mi文字以下 |
| 画像データ | 各16 MiB、複製後の埋め込み画像合計64 MiB |
| 画像デコード | 各辺16384px以下、1600万画素以下、デコーダー割当128 MiB以下 |
| ODT master-pageのスタイル複製 | automatic-stylesの複製合計16 MiB |

ZIPはディレクトリ件数と容量を検査してから開き、XMLの実際の読み取り量も制限する。
同じ画像への大量の参照はモデルへ複製する前に数える。ODTのtext:sもXML部品を
またぐ全体予算に含める。フォント、段落、用紙、画像の寸法とリスト階層を検証する。
JSON保存とPDF出力、Writerの復旧コピーにもモデル検証を適用する。
画像は縮小する前に寸法・画素数・割当量を確認し、PDF画像にも同じ制限を使う。
画面の画像キャッシュはすべてのセクションを対象にする。

## Calc

既存XLSXの64 MiB入力、4096 ZIP部品、8 MiB XML、128 MiB展開、1000シート、
100000セル、32 MiB文字列、100万セルの密な範囲制限に加え、次を適用する。

- ODSはcalamineの繰り返しセル／行を展開する前に、グリッドの範囲、100万セルの
  繰り返し・密な範囲、展開文字列の32 MiBを検査する。空の繰り返しセルも数える。
  ZIPのXMLは実読込も8 MiBに制限する。
- XLSはcfbで複合ファイルを検証し、4096エントリ、各ストリーム8 MiB、合計128 MiBに
  制限する。BIFF8の通常ワークシートを対象とし、古いBIFF形式、重複・不正なシート
  オフセットを拒否する。寸法、疎なセルの実範囲、セル・シート件数と共有文字列の
  参照による複製量をcalamineの割当前に検査する。数式の文字列展開も保守的に数える。
  旧形式パーサーのpanicは読込エラーとして扱う。
- CSVは32 MiB、200万フィールド、10万の非空セルに制限する。疎な巨大範囲のCSV出力は
  文字列を展開する前に拒否し、既存の保存先を保持する。
- 拡張子ではなく内容で形式を選ぶ。検査済みの同じバイト列を対応するパーサーへ渡し、
  不正な形式を別のパーサーで再試行しない。XLSBは既存どおり非対応。

## 検証結果

全356テスト、workspace/all-target Clippy（警告をエラー扱い）、UIビルド、
git diff --checkが成功。既存の形式往復・ゴールデン・セクションテストも通過した。
通常のBIFF8 XLSとODSを実際に読み込むテストを含む。

Linux Xvfb/Openboxで以下を確認した。

- Writer：巨大ファイル、巨大DOCX XML、ODTの合計空白展開、巨大JSON段落を拒否。
  日本語本文・元の保存先・元ファイル・Redoを保持し、その後の編集とSave Asが成功。
- Calc：XLSXの巨大ファイル・疎な範囲・展開容量に加え、ODSの繰り返しとXLSの巨大寸法を
  拒否。日本語のセル、元の保存先・元ファイル・Redoを保持。その後の保存結果をopenpyxlで確認。
- Writer：SIGKILL後の再起動で日本語の未保存本文を復旧。元ファイルは不変で、
  新しい保存先への保存と復旧コピーの削除が成功。
- Calc：SIGKILL後に未確定の入力、複数の日本語シート、数式、書式・寸法を復旧。
  保存結果をopenpyxlで確認し、元ファイルの保持と復旧コピー削除も確認。
- Impress：SIGKILL後に日本語本文・ノート、テーマ、複製したスライド、アクティブな
  スライド、図形配置、埋め込み画像を復旧。保存結果と元ファイルの保持、復旧コピー削除を確認。

これらはLinuxの既存MVP形式に対する検証で、Windows/macOSでの起動・IME・配布確認は
引き続き別の未達項目。入力制限は [PR #30](https://github.com/rsasaki0109/rust-office/pull/30) でmainへ統合済み。
回帰・実画面・復旧確認と統合の条件を満たし、安定性の残り5点を受け入れて現在値は85%。
