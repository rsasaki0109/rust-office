# 日常利用のロードマップ（当面の目標80%）

## 評価の範囲

目標は、Writer・Calc・Impress で日常的な文書・表計算・スライドを作成し、
保存、再編集、共有できる状態。Microsoft Office / LibreOffice 全機能との
互換性を 100% とした評価ではない。

2026-10-10（日本時間）の現在値は **75%（15 / 20 項目）**。下記の各項目を 5 点とする
プロジェクト内の達成度であり、品質の測定値や外部ベンチマークではない。
当初の45%（9項目）から、ODT 安定化と Writer 検索・置換、Impress のスライド操作・図形配置の完了で20点加算した。
Calc の書式・シート管理と Impress の発表・共有のマージ・受け入れ確認で、さらに10点加算した。
チェック済み項目も、既存の MVP 範囲の達成を示す。

項目を完了にするには、main へのマージ、対象の回帰テスト、実際の操作確認、
保存・再読込または配布確認の証拠を残す。テスト件数や PR 件数だけでは加点しない。
未マージの変更は進行中として扱う。

| 分野 | 配点 | 現在 | 未達の主要項目 |
| --- | ---: | ---: | --- |
| データ保護・安定性 | 20 | 15 | 復旧・大きな入力の制限 |
| Writer | 25 | 20 | セクションごとのページ設定 |
| Calc | 20 | 15 | 複数シートの集計・グラフ |
| Impress | 20 | 20 | 高度な互換性は MVP 範囲外 |
| 配布・使いやすさ | 15 | 5 | Windows/macOS、IME・アクセシビリティ確認 |
| 合計 | 100 | 75 | 80点に向けて残り5点 |

## 達成チェック

### データ保護・安定性（20点）

- [x] 保存失敗時に元ファイルと未保存編集を保持する。
- [x] 新規作成・Open・終了の確認と、失敗時の文書・保存先・履歴保持が機能する。
- [x] DOCX / ODT / PPTX / XLSX / CSV の壊れた入力と必要な参照の欠落を検出し、
  部分的な読み込みによる内容欠落を防ぐ。ODT は [PR #10](https://github.com/rsasaki0109/rust-office/pull/10) で完了。
- [ ] クラッシュ後の復旧用コピーと、読み込み・展開・描画の大きな入力に対する
  制限を備える。強制終了と復旧、制限超過後の編集継続を確認する。
  PPTX / XLSX の全体容量・モデル件数制限と Writer / Calc / Impress の復旧コピーを進行中。
  各変更のマージと他形式の制限が揃うまで加点しない。

### Writer（25点）

- [x] 表、埋め込み画像、リスト、リンク、基本ヘッダー／フッターを編集できる。
- [x] JSON / DOCX / ODT の基本保存・再読込と、レイアウトに沿う PDF 出力が機能する。
- [x] 検索・置換：日本語、次／前、全置換、該当なし、Undo/Redo を扱い、

  DOCX / ODT / PDF の保存・再読込で維持する。

### Impress（20点）

## 当面の80%までの順序

Calc の書式・シート管理と Impress の発表・共有を受け入れ、75%に到達した。
Writer のセクション設定が完了すると80%になる。
進行中の実装・PR は、完了条件を満たすまで加点しない。

1. Calc のセル書式・シート管理・行高／列幅（70%）。
2. Impress の発表・PDF共有・PPTX基本図形出力（75%）。
3. Writer のセクションごとのページ設定と各形式の保持（80%）。
   設定をまとめて変更・Undo するモデル API と、サイズ・余白の検証を [PR #27](https://github.com/rsasaki0109/rust-office/pull/27) で実装。
   ヘッダー／フッターダイアログは空白と未変更フィールドの書式を保持し、一度の Undo で戻す。
   セクション別の画面配置、設定 UI、DOCX/ODT/PDF の保持を実装し、全341テスト・Clippy・ビルドで確認した。
   新しい設定ダイアログの実画面確認は未実施のため、この項目はまだ加点しない。

80%は中間目標。復旧・入力制限、複数OS、IME等の検証を継続し、
下記の90%到達条件を長期目標として維持する。

## 進め方と完了判定

1. ODT 安定化を完了し、データ保護の既存動作を揃える。
2. Writer の検索・置換を、モデル、UI、書式・保存への影響を確認できる単位で実装する。
3. Calc のセル書式・シート管理と、Impress の図形・スライド操作を小さな PR で進める。
4. セクション互換性、発表・PDF、複数シート集計・グラフを進める。
5. 復旧・入力制限、Windows/macOS 配布、IME・アクセシビリティを検証する。

**90%到達条件**は18項目以上の完了に加え、データ保護の4項目、3 OS の配布確認、
主要なキーボード・IME 操作の確認が完了していること。残る2項目は未対応範囲として
明記する。重大なデータ損失・起動不能・保存不能が残る間は90%とは報告しない。

各 PR に再現例、変更後の動作、検証結果、互換性の限界を記載する。
完了項目に対応する PR・CI・手動確認の記録を更新し、再発時はチェックを戻す。
現在の機能と制約の詳細は [DEVELOPMENT.md](DEVELOPMENT.md) を参照。
